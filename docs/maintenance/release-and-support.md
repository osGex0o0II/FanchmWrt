# 发布与支持维护

发布、支持和安全响应需要可追溯的事实。不要把“已关闭”的 issue 自动解释为“已修复”，也不要把某个分支的构建结果推广为所有设备的支持承诺。

## 发布前检查

- 记录源码提交、目标、Profile、外部 feed 固定版本与 Linux 构建结果。
- 运行覆盖层测试、静态检查和与本次变更相关的软件包编译。
- 为镜像提供明确的设备与分区前提；不能确认时应标记为待验证，而不是给出通用刷写说明。

## 支持处理

问题报告应包含设备、版本、目标、配置变化、复现步骤和脱敏日志。硬件支持请求、功能建议与缺陷报告应分别记录，避免把产品需求误标为已确认故障。
